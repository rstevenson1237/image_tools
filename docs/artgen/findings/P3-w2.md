## What W2 gives a game repo

| Step | Command (skill `asset-production`) | What happens |
|---|---|---|
| briefs | `brief add / list / rm` (`/artgen-brief`) | validated entries in `art/briefs.yaml`; comments kept on edit (YAML document API) |
| autonomous run | `make [ids]` (`/artgen-make`) | scaffolds each brief from a template, names the next step for the first unfinished asset, records `final` (with open issues) when its pipeline completes, stops assets over `maxImageTokensPerAsset` |
| show | `gallery`, `status` (`/artgen-review`) | ≤ 12 finished assets per sheet with score and open issues; `brief → in-pipeline → final → approved → exported`, plus `revision` and `stale` |
| user answers | `approve`, `feedback --route base\|finish` (`/artgen-approve`, `/artgen-feedback`) | approve needs a passing gate and a review sheet (R6) and keeps the sheet in `art/sheets/approved/`; feedback opens the next base (form) or finish (pixels) version |
| hand edit | `import-edit <id> <png>` | diff against the final → the next `finish.vM.js` replays the previous finish, then the edits as colour tokens |
| export | `export [--pack] [--include-drafts]` (`/artgen-export`) | MaxRects atlases, `pack.json`, Aseprite JSON (array form), `src/art/assets.ts` with typed ids |
| restyle | `restyle` (`/artgen-restyle`) | renders every finished asset under the old (`art/directions/vN.json`) and new direction, before / after / token-diff sheet; changed assets go back to `final`, unchanged ones keep their approval |
| analytics | `analytics [--out]` | per-pass gains, revisions vs finishing, cost by kind/size/view, first-pass quality per template, regressions, user revision rate, model/effort table, budget suggestions |

The pass machine gained two stages: **`x1..`** — one extra autonomous base revision when the final still fails the gate
(`budget.extraAutonomousRevisions`) — and **user iterations** opened by feedback (`u1..` for a new base, `f2..` for a
finish revision). The base that gets finished is the latest user iteration if there is one (the user asked for it, even
if it scores lower), else the best-scoring base (R12). Budgets come from `art/artgen.config.json`: `revisionPasses` per
`perKind` and per importance `tiers` (hero 4 / filler 2 by default), `maxUserIterations` (feedback beyond it asks the
agent to escalate), `maxSheetEdge`. Every score records the stage's model + effort from `models`, wall time since the
asset's previous record, and Δ vs the previous base (or the bound base for a finish); `--model --effort --tokens-in
--tokens-out --ms` take measured values.

## Fixture runs (cloud session)

Each fixture ran a 10-asset brief through `make` with no questions mid-pipeline, then a simulated user round (approve,
feedback on both routes), a hand edit, a direction v2 + `restyle`, re-approval and `export`. **The user's choices were
simulated** (notes say so in every ledger line), and **every review was scored in this session by the agent that wrote
the asset** (no separate `art-reviewer` subagent run) — the scores are self-assessed, the drift risk D10 names.

## Numbers (30 assets, three fixtures)

| Pass | Mean score | Mean Δ | Regressions |
|---|---|---|---|
| r1 | 5.17 | – | – |
| r2 | 6.02 | +0.85 | 2 / 30 |
| r3 | 6.37 | +0.35 | 3 / 30 |
| f | 6.48 | +0.05 | 1 / 30 |
| u (user base) | 6.5 | +0.9 | 0 / 5 |
| f2+ (user finish / re-finish) | 6.67 | +0.21 | 0 / 12 |

- **Revisions do the work: +1.27 on average from r1 to the best revision, finishing +0.13.** v2 is the big step; v3 still
  helps (+0.35) and regressed 3 times (R12 kept the better version each time). No kind crossed the budget-suggestion
  thresholds (v3 ≤ 0.1 or ≥ 0.75 over ≥ 3 assets).
- **The finishing pass mostly finds nothing.** `px.fix.orphans` / `jaggies` / `corners` rarely change clean T2+ output (their
  speckle is material noise, which reads as texture); a finish added half a point only when it targeted something the
  review named (a lid edge, a chipped capital, hoop highlights, a calmer bevel grid). The skill now says so.
- **Users asked for form more than pixels:** 5 base-route vs 7 finish-route rounds over 30 assets (the finish count includes
  the 3 hand edits, which are recorded as finish feedback); a base round added +0.9, a finish round +0.2.
- **Cost:** 42.6k estimated output tokens and 115.6k review-image tokens for the three runs (≈ $1.32 at artlab's price
  basis), ~$0.04 per asset; 8-facing walk sheets are the expensive reviews (2–2.5k image tokens each).
- Wall time per pass is the gap between ledger records (the session's pace, ~10–20 s); one 25-minute outlier in
  billboard-crawler is a worker restart mid-run.

## Engine, CLI and gate changes found on the way

- **Path parser bug:** numbers in exponent notation (`1e-16`, what `Math.sin(Math.PI)` interpolates to) failed with
  "expected a number"; fixed with a test.
- **Review sheets for animated assets:** 8 facings × idle + walk is 40 cells; as one strip the sheet shrank to illegibility.
  Big renders now review as one row per unique facing (mirrored west facings left out), and the earlier versions on the
  sheet show their first facing only. Tiles review as a 3×3 repeat, iso diamonds staggered (the rectangular repeat hid
  gaps between diamonds). Rows use the direction's background; anchors of the asset's kind are shown under every sheet.
- **The gate kept catching real things:** glow pixels on a prop (not in the prop palette), an iso floor without its outer
  line (`line.outer: dark` applies to iso diamonds, which have a silhouette), assets that ran off the frame.
- **Cubes renderer merges touching boxes of one material:** rubble blocks fused into one slab until they had one-unit gaps.
- **Brief kinds without their own scale key or template borrow one** (creature → character, tileset/texture → tile, viewmodel →
  large, ui-icon → prop). Characters/creatures with facings or a walk start from the new **walker** template.
- **`lock` archives every direction version** in `art/directions/vN.json` (restyle needs the old one); the fixtures' v1 was
  archived on their v2 lock.
- **The CLI bundle needs a real `require`:** `yaml` is CommonJS and requires `process`; the esbuild banner provides one.
- **`detail` procedural layer:** Bollinger-style mask templates stamped onto a part (seeded, mirrored, tiled); used for the
  skeleton knight's pitted mail (it regressed that version — too much speckle at 24 px).
- Status rule: a restyle that changes no pixel carries the approval (and an export after it) over.
