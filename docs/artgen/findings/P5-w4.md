## What W4 gives the user

| Tool | What it does |
|---|---|
| **Art Direction** | edits the locked direction or any candidate as a form: ramps (edit swatches, add / drop, regenerate a hue-shifted ramp around a base colour), Lospec `.hex` / GIMP `.gpl` import and extraction from a reference image (dropped on a pixel-mode `CanvasStage`; median cut → ramps in a tray, each assignable to a ramp), outline / shadow / background, camera (view, facings, pixel scale, light), scale per kind, line, shading, detail. A **live style tile** of the probe set re-renders 0.45 s after each edit, beside the locked direction and any candidates ticked for comparison, with gate failures listed. **Save draft** writes `art/candidates/<name>.json`; **lock** does what `artgen direction lock` does. |
| **Asset Review** | gallery by status (final first: what waits for the user), thumbnails of every final; per asset: the final at an integer zoom in context (iso floor, 3 × 3 for tiles, game background or checker), cell picker for multi-facing assets, the **pass timeline** (version, pass, score, blind score, reviewer, gate, review note), A/B compare of any two versions on the same cell with a changed-pixel mask, conformance checks and metrics, feedback and approval history. **Approve** (with note) and **Request changes** (route: pixels → finish, form / colour → base; drag on the sprite to pin the note to a region). An **Analytics** panel shows per-pass gains, cost per asset and kind, user revision rate, review independence, regressions and budget suggestions. |
| **Asset Lab** | any asset and version; sliders / toggles / choices / ramp swaps from the module's param schema, seed and variant; playback **through the W3 runtime's canvas2d adapter** (`createPack` on a one-asset pack built in the worker): state, facing or a turning angle (mirror-aware `face`), frame scrub when paused, zoom, background; **export** the asset alone as a pack zip (`pack.json` + atlas). Writes nothing to the project. |

All three share one open project (switching tools keeps it) and a project bar: **Open game folder…** (File System Access;
the repo root or its `art/` folder), **Reopen** the remembered folder (the handle is kept in IndexedDB; the browser asks for
permission again each session), **Reload**, and the **zip fallback** where there is no directory picker: import a zip of the
repo or its `art/`, work in memory, **Download art.zip** (to unpack over the repo root) with a list of the files changed.

## How it reaches the same files as Claude Code (SPEC §13.3)

- **Engine in a worker.** `src/workers/artgen.worker.ts` runs the same `@artgen/core` build the CLI bundles (resvg wasm
  included) over a snapshot of the art folder: sources, JSON, YAML, the ledger and the anchor PNGs (renders, sheets and
  references stay on disk). Asset modules are imported there — never on the page (D17) — as blob URLs whose relative imports
  (`import * as prev from './finish.v1.js'`) are rewritten to the blob URLs of the files they name.
- **One reading of the files.** `src/core/project/engine.ts` mirrors the CLI's derivations over the snapshot (status,
  pass state, finish-stale, final hash, renders + conformance, analytics, probe renders, lock). `engine.test.ts` runs it
  against the CLI on all three fixture repos: identical status rows (status, final, score, gate, issues, why), finals
  pixel-identical with the same gate, the same feedback entry, the same refusal to approve a non-final, and the same
  `direction.json` and anchors after a lock. Config defaults, budgets, the placeholder check and `finishBaseOf` moved into
  core (`w2/config.ts`) so the CLI and the UI share them rather than copy them.
- **Writes are plans.** The worker returns file operations; the store applies them. Every action re-reads the folder
  first, plans in the worker, then checks that `ledger.jsonl`, `direction.json`, `briefs.yaml` and the config, and every
  file it will overwrite, are unchanged on disk since that re-read (D5: Claude Code may be writing); otherwise nothing is
  written and the user is told to try again. Ledger lines are **appended** (`createWritable({ keepExistingData })` + seek
  to the end), never rewritten. UI lines carry `by: "user"` and `"via": "image-tools"`.
- **Feedback reaches Claude Code.** A user-opened step now quotes the user: `pass next` / `make` print
  `— user: "<note>" (region x,y,w,h 5,5,6,5 of idle/s/0)` (core `planPasses`; the CLI's and the UI's `feedbackOf` carry
  note, region and cell). Before this, a note typed in Claude Code was in the agent's context anyway, but one written in
  the UI would only have been in the ledger. The managed `CLAUDE.md` section and the art-direction / asset-production
  skills (dist **0.7.0**) say what `via: "image-tools"` lines mean and that a lock made in the UI needs a restyle.

## Framework pieces (SPEC §13.2)

`WorkerKind` `'artgen'` in the ref-counted pool; registry tool **groups** (sidebar sections "Image tools", "Art pipeline")
and `#tool-id` deep links; shared `StatusBadge`, `PixelPreview` (integer zoom, checker / colour / context backdrop, 3 × 3

whole fractions, no smoothing, placement snapped to whole pixels; the existing tools don't set it).

## Found on the way

- **Without the note in `make`, UI feedback would have reached the ledger but not the agent.** P3's pass machine named the
  version a feedback round opens, not what the user said. The step now quotes it (above).
- **Two reads racing.** Switching to Asset Review starts a read; Reload right after starts another, and the slower first
  one could land last and show pre-reload rows next to a post-reload detail. Every read is now ticketed (latest wins).
- **Previews have to fit the context, not the sprite.** An iso character in context is 3 × its size; zooming to fit the
  sprite made the iso floor 1000 px tall and pushed the drag target off screen. Zoom fits what is drawn.
- **Long sheets don't compare.** An 8-facing walker's strip is 32 cells wide; A/B compare now shows the selected cell
  (state / facing / frame) in both versions.
- **`checkJs` off for the app.** `engine.test.ts` imports the CLI, which pulls in core's benchmark asset modules (`.js`);
  `svelte-check` with `checkJs` flagged their untyped params. The app has no JavaScript sources of its own, so nothing else
  changes.
