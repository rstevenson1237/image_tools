# P4 findings — W3: runtime component

Date: 2026-10-06 · Phase: [PLAN P4](../PLAN.md#p4--w3-runtime-component-m) · Code: `packages/artgen-runtime` (core +
adapters), `packages/artgen-cli/src/runtime.ts` (`export --runtime`), `packages/artgen-dist` (ships `tools/artgen/runtime/`,

## What W3 gives a game repo

| Piece | What it does |
|---|---|
| `artgen export --runtime [--force]` | exports the packs as before, then vendors the runtime core + the adapters in `art/artgen.config.json` (`runtime.adapters`) into `src/art/runtime/`, stamped in `runtime.json` (version, adapters, hash per file). Re-export upgrades untouched files, keeps and reports edited ones unless `--force`, and removes adapters dropped from the config. `pack.json` now says which runtime it was exported for (`"runtime": "1.0.0"`). |
| `loadPack(url, adapter)` | fetches `pack.json`, decodes the atlases exactly (no premultiply, no colour conversion), uploads them through the adapter, builds palette-swap atlases once; refuses another pack format or runtime major |
| `pack.sprite(Assets.x, { state, variant, parent })` | state × facing × frame machine: per-state fps and loop, `play`, `face(angle)` / `faceToward(dx, dy)` (nearest exported facing, else a mirrored one), `update(dtMs)`, `at(x, y, z)`; the node is only touched when the shown frame changes |
| `pack.tiles(Assets.t)` | `resolve(mask)` for `wang16` / `blob47` layouts (P6b exports them), `pick(x, y)` per-cell variants, `node(x, y, …)` |
| `pack.effect(Assets.e, { parent, loop })` | `spawn(x, y, z)`, `update(dt)` disposes finished one-shots; `loop: true` keeps a flame burning |
| `isoToScreen`, `screenToIso`, `depthKey`, `obliqueToScreen`, … | placement and draw order for iso and ¾ views |
| adapters | `pixi` (Pixi.js v8 `Sprite`s, `zIndex` depth sorting, `pixiStrip` for `AnimatedSprite`), `three` (`Sprite` billboards sized by `pixelsPerUnit`, `billboardAngle`, `tileTexture`), `canvas2d` (reference: `Canvas2DLayer.draw(ctx, zoom)`) |

Typed ids: `Assets` entries from the generated `assets.ts` type `play()` states and `variant` names (`'walk'`, `'bloody'`), so
they autocomplete and a typo fails `tsc`; plain string ids still work, untyped.

Acceptance (PLAN P4):

- **Each fixture game's art code < 20 lines** — 12, 11, 12.
- **Typed ids autocomplete** — `typed.test.ts` (`@ts-expect-error` on a wrong state and variant, checked by `tsc`) and the
  fixture typecheck (the iso room table was rejected until its variant and state types were exact).
- **Contract tests pass for all three adapters** — one suite (`contract.ts`, 8 cases: textures + swap atlases, first frame +
  anchor, play / face / update, mirrored facings flip about the anchor, positions, swap textures, effects attach and
  dispose, tile nodes) runs against `canvas2d`, `pixi` and `three` with an inspector each.
- **Runtime unit tests** — frame selection, fps timing and looping, facing math (8 facings, mirror-aware, single facing),
  `wang16` / `blob47` masks (all 256 masks round-trip), effects, iso / oblique round trips and depth order, swaps, manifest
  checks, and every asset × state × facing × variant of the three exported fixture packs.
- **Core < 8 KB min+gz without adapters** — 3.7 KB (8.9 KB minified), checked in `size.test.ts`, which also checks that core
  files import only each other and each adapter only its engine.
- **A stub fourth adapter without touching the core** — `adapters.test.ts` adds an SVG-style record adapter written only
  against the public API; it passes the same contract.

## Found on the way

- **The swamp fixture's palette swap was backwards.** The P3 brief said `pale: { skin: cloth }`, but the bog goblin's
  mud-green skin is drawn with the `cloth` ramp, so the swap recoloured 6 pixels and the "pale" goblin looked identical.
  Seen only once the swap was on screen; the brief now says `pale: { cloth: skin }` and the re-export shows a pale goblin.
  (iso-dungeon's `bloody: { cloth: accent }` was right: 44 px of tabard.) A swap that hits almost nothing deserves a
  warning at export — open item.
- **Adapter interface, as built:** `setPosition(node, x, y, z?)` joined the spec's five methods (effects spawn at a
  position; z is `zIndex` in 2D, world z in 3D), plus optional `attach` and `disposeTexture`. `setFrame` gets a frame rect
  that carries its atlas texture (an asset's frames can span atlases), `setAnchor` the frame size.
- **Palette swaps are recoloured atlases**, built once at load, instead of Pixi's colour-map filter in the spec: every
  adapter gets them for free and no shader runs per sprite. Cost: one atlas copy per (asset, swap) — trivial at fixture
  sizes; revisit if a pack has many swaps over large atlases.
- **Mirroring about the anchor:** Pixi flips with `scale.x = -1`, which mirrors about the anchor; three flips by a negative
  UV repeat, which mirrors about the quad centre — so the three adapter moves the sprite centre to `1 − ax/w` when
  flipped. The contract test checks the anchor pixel stays put in every adapter.
- **Exported packs need no mirroring today:** `renderAsset` renders all 8 facings (west ones mirrored at render time), so a
  pack's walker has 8 distinct strips; the runtime's mirror path serves packs exported with fewer facings and side-on
  sprites (`['e']` turns around).
- **Billboard facing** is the heading expressed in the camera's frame: forward = camera → entity on the ground plane,
  right = forward × up; facing the camera reads `s`, moving to the camera's right reads `e`. The crawler's ghoul walks a
  circle while the camera orbits the other way, so all eight facings come up within one lap.
- **Vendored files carry a header but not the CLI version**, so a distribution bump doesn't rewrite them; the stamp holds the
  generator. The fixture test compares every vendored file with what `export --runtime` would write now.

## Open items

- **Acceptance in a local session** (the user's own machine and browser) is still to do; this run is the cloud session with
  headless Chromium (SwiftShader). Like P2/P3, the fixtures' user choices were simulated.
- **Sub-path deploys:** `assets.ts` writes `Packs.main` as `/assets/main/pack.json`; a game served from `/<repo>/` (GitHub
  Pages) must prefix its base URL (`import.meta.env.BASE_URL`). Generating a base-relative URL is a small export change.
- **Drafts** (`--include-drafts`) are flagged in the pack (`pack.isDraft(id)`), but the runtime doesn't watermark them yet.
- **three's alpha cut-out** (`alphaTest` 0.5) drops translucent pixels (soft shadows); fine for the current packs, which are
  opaque-or-clear. A sorted transparent mode can come with P6.
- Autotile layouts in `pack.json` (`autotile`, `map`) arrive with P6b; the resolver is ready and unit-tested. Sprite-stack
  planes, FP wall sets and `.glb` voxel models arrive with P6a / P6d.
