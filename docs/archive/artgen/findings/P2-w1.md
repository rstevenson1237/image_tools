- `.claude/skills/artgen` (pipeline, rules, pitfalls, references for T2+, finishing, review, direction),
  `.claude/skills/art-direction` (W1), `.claude/agents/art-reviewer.md`, commands `/artgen-init`, `/artgen-direction`.
- `tools/artgen/`: `artgen.js` (CLI, 266 KB) and `artgen-mcp.js` (MCP server, 206 KB) as single-file esbuild bundles,
  `resvg.wasm` (2.4 MB), templates, `VERSION`, `MANIFEST.json`, and a `package.json` with `"type": "module"`.
- `.mcp.json` gains an `artgen` server; `CLAUDE.md` gains a managed section between `artgen:begin/end` markers.
- `art/` scaffold (`artgen init`), including `art/package.json` with `"type": "module"` so asset sources are ESM
  whatever the game's own `package.json` says (found while installing into a `"type": "commonjs"` repo).

`update` replaces files whose hash still matches the manifest, keeps locally edited ones unless `--force`, removes
files the new version no longer ships, and never touches `art/` or other MCP servers. The install smoke test
(`packages/artgen-dist/test/dist.test.ts`) builds the distribution, installs it into a scratch repo and runs the W1
flow and an MCP session from the installed files only. CI publishes the build to the `artgen-dist` branch
(`.github/workflows/artgen-dist.yml`, after the package tests pass on `main`); the publish script was exercised
against a local bare remote (first publish, unchanged build, follow-up commit).

**Command naming (settled, D1):** skills are the interface; the committed install adds `/artgen-init` and
`/artgen-direction` (`.claude/commands/artgen-*.md` — no namespace outside plugins), the plugin layout gives
`/artgen:init` and `/artgen:direction`.

## The W1 workflow as built

| Step | Command | Output |
|---|---|---|
| interview | (skill) → `art/interview.json` | pitch, view, scale, mood, colours, rules |
| candidates | `direction candidates --from art/interview.json` | `art/candidates/{a,b,c}.json` + the probe set in `art/probes/` |
| style tiles | `direction tile [names]` | `art/candidates/style-tile-rN.png`, one column per candidate, gate result per probe |
| short pipeline | probe `base.v2.js` (one revision), `finish art/probes/<kind>` | game-specific probes, finished |
| choose / mix | `direction mix <base> --palette a --line b …` | `art/candidates/mixN.json` |
| lock | `direction lock <name> --note "…"` | `art/direction.json` (locked, v1 / v+1), `art/anchors/*.png`, `art/direction.png` |

Candidates differ on four axes (§4.2): **A faithful** (palette from the pitch, dark outline, 3 bands, head 0.4),
**B bold** (saturated, hue-rotated, selout, 4 bands, head 0.5), **C muted** (darker near-duotone, no inner lines,
2 bands + Bayer dither, head 0.32). Every generated direction carries the same eleven **role ramps** (skin, hair,
cloth, leather, metal, wood, stone, dirt, grass, accent, glow), so probes and templates render under any candidate
without edits (R11). Setting words in the pitch pick key/accent hues and the ground and growth colours (snow,
sand, basalt, moss, …); an imported or extracted palette feeds candidate A.

The probe templates (character, prop, tile, effect × topdown, iso; other views fall back to topdown) draw in
coordinates relative to `ctx.size`. Before the fixtures, every template passed the gate under every candidate in a
36-combination matrix (6 pitches × 2 views × 3 scales = 432 probe renders).

## Engine and gate changes found on the way
- **Finishing ops broke `selout` lines.** `px.light.rim` (and every fill op) treated the silhouette's darkest-ramp
  pixels as material and lightened them, failing the line check on every selout candidate. Under `selout` the
  silhouette is now line, like the outline colour. Benchmark renders are unchanged (both bench directions use `dark`).
- **Conformance:** tiles wrap at their borders (a full-bleed tile has no silhouette); the light-direction check is
  skipped for effects (emissive) and tiles (a ground plane); under `selout`, the light check ignores the line itself.
- `--direction` paths resolve from the working directory (they resolved from the asset dir).
- The bundled CLI and MCP server share modules, so the "am I the entry point" guard moved from `cli.ts` to `bin.ts`
  (the MCP bundle was printing CLI usage on stdout).
- The pass machine re-finishes when a revision written after the finish beats its base (probes are finished early
  in W1, then taken through the full pipeline after lock).
- The per-kind palette gate caught real authoring choices in all three fixtures (a lantern's glow on a character,
  moss on a prop, a wooden shield): the agent either tailors the candidate (`perKind`) or changes the art.
